# 새신자 등록

영어 설계: [Newcomer Registration](./2026-09-27-newcomer-registration-design.md)

## 목표

처음 온 방문자가 홈의 새가족 안내 한 줄에서 새신자 등록을 열 수 있다. 질문과 답변은 교회 Microsoft Form에 남긴다. 웹사이트는 폼 링크와 안내 문구만 저장하고, 관리자가 켰을 때만 안내를 보여 준다.

## 판단

새신자 등록은 계속되는 목양이고, 교회의 새신자 폼은 하나뿐이다. 이것을 온라인 신청의 한 항목으로 두면, 한 건을 위해 규칙이 여러 개 붙는다. 특별 분류, 두 건일 때의 처리, 마감일 없음, 다른 버튼 문구, 홈 ‘지금 신청’에서 빼기 같은 것들이다. 게다가 안내 문구는 사이트 설정에서, 링크는 신청 탭에서 고치게 된다.

그래서 새신자 등록은 홈의 독립된 안내 한 줄로 두고, 한 곳에서 관리한다. 위치는 사이트 설정 → 문구 → 홈 → 새가족 등록이다. 켜기/끄기, Microsoft Forms 링크, 한·영 문구가 한 화면에 있다. 온라인 신청 기능은 바꾸지 않는다.

개인 답변은 목회 담당자의 Microsoft 365에 남는다. 후속 상태(새 등록, 연락함, 연결됨)는 Form 응답 시트에 둔다. 웹사이트는 접수 내용을 저장하지 않고, 상태 목록도 보여 주지 않는다.

## 범위

포함:

- 사이트 문구의 `home.welcome`: 켜기/끄기, 폼 링크, 작은 제목, 제목, 소개, 버튼 문구
- 홈 ‘처음 방문 안내’ 바로 아래의 새가족 안내 한 줄
- 안내가 켜져 있을 때 폼을 여는 첫 화면 보조 버튼
- 홈 문구 편집 화면의 ‘새가족 등록’ 칸 (‘처음 방문 안내’ 바로 다음)
- 폼 링크의 화면 검증과 서버 검증

포함하지 않음:

- Microsoft Form을 만들거나 페이지 안에 삽입
- 답변 저장, 등록 메일 발송, 웹사이트에서 연락함·연결됨 표시
- 온라인 신청, 자료·신청 목록, 홈 ‘지금 신청’의 변경
- 새 공개 페이지나 새 관리 페이지

교회가 자기 테넌트에 Form을 만든다. 이름과 연락 방법 하나만 필수다. 참석 예배, 신앙, 교회를 알게 된 경로, 주소, 가족, 목장, 기도는 선택이다. 관리자가 링크를 붙여 넣고, 안내를 켜고, 저장한다. Form 주인이 응답 시트에 후속을 적는다.

자료·신청 목록에도 새신자 등록을 두고 싶으면, 편집자가 같은 링크로 일반 신청을 하나 만든다. 그 신청은 기존 신청 규칙을 그대로 따르고, 따로 특별하게 다루지 않는다.

## 방문자 경험

안내가 켜져 있고 링크가 올바른 Microsoft Forms 주소이면, 홈은 ‘처음 방문 안내’ 바로 아래에 가로로 넓은 안내 한 줄을 보여 준다. 방문자는 ‘와서 보기’ 다음에 ‘연결되기’를 읽는다. 첫 화면 보조 버튼도 안내의 버튼 문구로 같은 폼을 연다. 안내가 꺼져 있으면 그 자리에는 오시는 길 버튼이 나온다.

예배 시간, 주소, 지도, 길찾기는 ‘처음 방문 안내’ 한 곳에만 있다. 첫 화면 주 버튼이 그곳으로 가고, 첫 화면 아래 줄은 성도용 바로가기(설교, 행사, 자료)다. 다음 걸음 카드는 목장, 기도, 일반 문의이고, 따로 방문 카드는 없다.

안내 왼쪽에는 작은 제목, 제목, 소개가 있고 오른쪽에는 주요 버튼 하나가 있다. 좁은 화면에서는 버튼이 글 아래로 내려간다. 모든 문구는 언어 전환을 따른다.

버튼은 폼 링크를 새 탭에서 연다. `rel="noopener noreferrer"`를 붙인다.

안내가 꺼져 있거나, 링크가 비어 있거나, 올바른 Microsoft Forms 주소가 아니면 안내는 나타나지 않는다. 어느 경우든 홈의 나머지는 같다.

안내는 홈의 오가닉 스타일을 따른다. 민트에서 흰색으로 이어지는 배경, 은은한 금색 빛, 기존 `home-kicker`와 `home-button--primary`, 다른 홈 구역과 같은 둥근 모서리를 쓴다. 다른 홈 구역처럼 밝은 테마와 어두운 테마 변형도 둔다.

## 사이트 문구

`SiteCopy['home']`에 추가한다.

- `welcome.enabled`: 불리언, 기본값 `false`
- `welcome.formUrl`: 문자열, 기본값 빈 값
- `welcome.kicker`: 새가족 / New here
- `welcome.title`: 새가족으로 연결해 드릴게요 / Let us help you get connected
- `welcome.intro`: 이름과 연락처만 남겨 주시면 담당자가 목장과 교회 생활을 편하게 안내해 드립니다. 나머지는 알려 주셔도 좋고, 넘어가셔도 괜찮습니다. / Leave your name and a way to reach you, and we will help you find your place in church life. Everything else is optional.
- `welcome.buttonLabel`: 새가족 등록하기 / Register

`parseSiteCopy`는 `enabled`가 정확히 `true`일 때만 켜진 것으로 본다. `formUrl`은 앞뒤 공백을 빼고, `forms.office.com` 또는 `forms.microsoft.com`의 https 주소이고 500자 이하일 때만 유지한다. 그렇지 않으면 빈 값이 되어 안내는 숨는다. 빠진 문구는 위 기본값을 쓴다.

## 설정 화면

사이트 설정은 이미 관리자 전용이므로, 관리자만 안내를 바꿀 수 있다.

‘새가족 등록’ 칸은 두 묶음이다.

- 연결: 홈에 표시(켜기/끄기), Microsoft Forms 주소
- 문구: 작은 제목, 제목, 소개, 버튼 문구 (각각 한국어와 영어)

문구 네 칸은 기존 한·영 입력 규칙을 따른다. 두 언어 모두 필수이고 400자 이하다. 안내가 켜져 있을 때 링크가 비어 있거나 올바른 Microsoft Forms 주소가 아니면 문구 탭의 검증 오류가 되고, “Microsoft Forms 주소를 입력해 주세요.” / “Enter a Microsoft Forms link.”와 함께 저장이 막힌다. 꺼져 있을 때는 링크를 비워 둘 수 있다. 다만 비어 있지 않은데 올바르지 않은 링크는 그때도 오류다.

저장하지 않은 변경 표시, 저장 바, 되돌리기는 지금 그대로 쓴다.

## 서버

`PUT /api/site-settings`는 `siteCopy.home.welcome.formUrl`이 비어 있지 않고 https Microsoft Forms 주소도 아니면 400으로 저장을 거절한다. `api/shared/applications.js`의 `isMicrosoftFormUrl`을 다시 쓴다. 사이트 문구는 이미 JSON으로 저장되므로 데이터베이스 스키마는 바꾸지 않는다.

## 실패

사이트 설정을 불러오지 못하면 홈은 기본 문구를 쓰고, 기본값에서 안내는 꺼져 있다. 저장된 링크가 올바르지 않으면 깨진 버튼 대신 안내를 숨긴다. 저장이 거절되면 저장된 설정은 그대로다.

## 확인

단위 테스트:

- `parseSiteCopy`의 기본값은 꺼짐, 빈 링크
- `parseSiteCopy`는 올바른 Forms 링크를 유지하고, Forms가 아니거나 https가 아닌 링크는 버린다
- `enabled`는 불리언 `true`일 때만 켜짐
- 안내는 켜져 있고 링크가 올바를 때만 그려진다
- 설정 검증은 켜져 있을 때 비어 있거나 올바르지 않은 링크를 잡고, 꺼져 있을 때 빈 링크는 허용하며, 꺼져 있어도 비어 있지 않은 잘못된 링크는 잡는다
- 사이트 설정 API는 Forms가 아닌 링크를 거절하고 올바른 링크는 받는다

브라우저 확인은 데스크톱과 모바일 너비, 한국어와 영어, 교회·밝은·어두운 테마에서 한다. 안내를 켜면 ‘처음 방문 안내’ 아래에 나타나고, 안내 버튼과 첫 화면 보조 버튼이 새 탭에서 폼을 연다. 끄면 안내가 사라지고 첫 화면에 오시는 길 버튼이 돌아온다.

## 완료 기준

교회 계정이 없는 방문자가 홈에서 자기가 고른 언어로 새가족 안내 한 줄을 보고, 한 번 눌러 교회 Microsoft Form에 도착한다. 개인 답변은 웹사이트 데이터베이스에 남지 않는다. 관리자는 한 곳에서 안내를 관리하고, 안내를 끄면 안내 한 줄이 사라지고 첫 화면에 오시는 길 버튼이 돌아온다.
